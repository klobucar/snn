# Iowa historical partisanship and scenarios

Schema version 1. Counts are exact source integers; derived shares are fractions. CSV empty cells mean unavailable or not supplied, never zero. The FIPS key is a five-character county code; state footer FIPS is blank here and explicitly maps to the turnout worker's state code `19`. County Page is `19145`. No separate numeric county ID appears in the canvass; that field stays blank. County names are native SOS labels joined to the retained Census county-code table.

[sources.json](sources.json) pins read-only original gzip assets by path, entity/stored SHA-256 and byte count, URL, actual parent, retrieval UTC, final URL, HTTP status/headers and known redirects. A filename repair is labeled as an alternative, not an actual page link. Older unknown redirect history stays unknown; [http-refresh.json](http-refresh.json) independently captures subsequent complete request chains. A later successful response does not erase an earlier challenge. Compression covers lossless HTTP entity bytes after transport decoding. Originals remain authoritative for XML/ZIP elements not repeated in derivatives. [asset-manifest.json](asset-manifest.json) covers every owned output except itself; no artifact may reach 40,000,000 bytes.

## Scenario contract

[scenario-settings.json](scenario-settings.json) is authoritative: three preference baselines, each with three historical all-candidate county volume mixes and a native historical pair-volume check. Low uses 2022 Senate actual volume, base 2024 president, high 2020 Senate. These labels describe observed statewide volumes, not a 2026 range or probabilistic forecast. In crossed scenarios, `V_c` is the actual chosen county candidate-plus-generic volume; `p_c=(D+R)/A` comes from that county's preference contest; pair pool `T_c=V_c*p_c`. Native-pair cases use exact integer D+R. No population or fabricated Senate denominator is used.

[scenario-other-candidates.csv](scenario-other-candidates.csv) fixes each named nonmajor candidate and generic Write-in separately at `V_c * candidate_votes/A_preference`. They never become Democratic votes. Historical integer data are untouched. Fractional scenario values are expectations. [state-scenarios.csv](state-scenarios.csv) has 36 rows; [county-target-scenarios.csv](county-target-scenarios.csv) has all 99 counties for each. Pair weight is `T_c/sum(T)`, all-candidate weight `V_c/sum(V)`. D share `s` and margin `2s-1` have distinct units. Unbounded tie shift is `(R-D)/(2*(D+R))` at native weights; more generally `(target_net-baseline_net)/(2*sum(T))`. Pair D+1 target net is `.01*sum(T)`; all-candidate D+1 is `.01*sum(V)`. County target net `T*(2q-1)`, gain `2T*(q-s)`, one D-share point gain `.02T`, and signed statewide pair-margin contribution in points `100*county_net/sum(T)` use the same pools. All-candidate D+1 requires a larger pair-share shift whenever other votes exist.

The solver exposes the unbounded shift and applies `clip(s+delta,0,1)` with bisection if needed. It reports feasible/unbounded, feasible/bounded, impossible, no-positive-pool and unavailable inputs distinctly. Negative shifts and baseline-already-at-target cases remain signed; no required improvement is invented. No historical scenario currently clips, but synthetic tests exercise clipping. Separate other-candidate totals are checked against D under each scenario. A tie is not an integer win; a one-vote plurality or explicit margin cushion must be specified.

[selected-county-break-even.csv](selected-county-break-even.csv) holds every other county at the scenario's named preference contest and volume mix. It solves `(target_net-other_net+T_selected)/(2*T_selected)` for every county and each goal. Shares above one are impossible under those fixed assumptions, below zero already secured; the clipped display is not a feasible solution claim. [selected-native-unit-example.json](selected-native-unit-example.json) varies one historical 2022 Polk reporting label/method with every other historical vote fixed, explicitly without current geographic interpretation.

`calculate.py --live-json INPUT.json` is an offline arithmetic interface to `conditional()`. Inputs are counted D/R/other, and a list of remaining rows containing unique `key`, nonnegative `pair_votes`, nonnegative `other_votes`, and `d_share` in [0,1]. Optional `selected` defaults to `ALL`; `margin` defaults zero; `denominator` is `pair` or `all-candidate`. Counted votes never change. Target net uses the **final** denominator, counted plus all remaining pools, even when one county is selected. Missing, invalid, duplicate and absent selected keys yield unavailable. Zero pools and impossible thresholds retain explicit status. [live-remainder-examples.json](live-remainder-examples.json) is synthetic arithmetic, not a remaining-vote estimate, roster, collector or forecast.
