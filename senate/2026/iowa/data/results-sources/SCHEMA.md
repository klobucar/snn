# Iowa official publication research contract

This package is a source investigation, not a live collector, a geographic crosswalk or a calibrated forecast. Run scripts with `PYTHONDONTWRITEBYTECODE=1` from repository root. Only `official-results.md`, `data/official-results-sources.csv` and this directory are written. No Git operations are part of the workflow.

`acquisition-ledger.json` retains one record per bounded request, including exact requested/parent/final URLs, literal link labels, UTC retrieval, status, redirect chain and response headers, decoded HTTP-entity SHA-256/bytes, request headers, and every stored gzip object's SHA-256/size. Transport decoding is performed by requests; gzip storage is lossless over those decoded entity bytes. Empty403 bodies have a real empty-entity hash; a connection failure has no entity/hash. Source HTTP Date and Last-Modified are never vote clocks. No status is inferred from a successful wrapper or a search rendering.

Every stored object is strictly below40,000,000 bytes. An entity longer than30,000,000 decoded bytes is split into exact ordered30,000,000-byte chunks, each independently gzip-compressed. Concatenating the decompressed `parts` in ledger order reconstructs the complete original entity. There is no truncation, silent filtering or geometric simplification. `asset-manifest.json` pins all owned assets except itself and `validation.json`, avoiding circular hash references; validation pins that manifest. Existing peer originals are referenced once through `dependencies.json` rather than downloaded again.

`auditor-directory.json` is the complete99-county authority inventory parsed from the actual SOS auditor directory. Names are matched to the frozen canonical county contract, then independently checked against the retained Census2020 county table. Its `source_position` is an HTML directory position, never a native county ID. `official-results-sources.csv` has99 rows in largest-first contract order. `investigation_scope` is exactly41 `deep_priority` and58 `discovery_only`. Discovery rows describe the SOS authority link and tested response only, plus separately identified historical source availability. They do not claim current feed investigation equal to the priority set.

`counties/<FIPS>.json` has one individual investigation record for each exact priority county. It includes the authority chain, all tested source IDs/URLs/statuses, actual current-publication finding, county-specific gap, relevant native historical identity/count/control context, no November approval, and explicit manual backup responsibility. `county-notes.json` contains the reviewed county-specific findings used to build them. IDs in route paths, worksheet names, XML keys, GMD files, ArcGIS items and PDF document numbers remain distinct from FIPS.

`extracts/<source>.json` retains every parsed HTML link/resource occurrence with literal href/attributes, source line/column and ordinal; duplicates remain. HTML `<base>` changes URL resolution. Earlier wrong-relative attempts remain errors in the ledger. `embedded-views.json` decodes observed percent-encoded ArcGIS site JSON and identifies the exact source character offset and JSON pointer for each HTML card. `dubuque-page-views.json` identifies actual documented item-data page fields separately from the root site shell. Commented links remain in original bytes but are not active links in the HTML parser. Web tool observations in `web-access-observations.json` are rendered/search evidence only, with no fabricated original response hashes/headers.

`source-identity-inventory.json` classifies every retained entity, including irrelevant navigation/assets, failed requests, viewer shells, old elections, native JSON and inspected PDFs. `source-view-position-inventory.jsonl.gz` conserves every HTML link/resource occurrence and every extracted PDF layout line (physical page and line); pdftotext is a derivative, not a replacement for original bytes. Source-native election dates, raw prefixes, repeated positions and omitted/blank fields remain available. A source route's numeric IDs are labeled route-only unless verified against a payload.

`native-constituent-inventory.jsonl.gz` conserves all13,558 exact constituent objects from the final frozen priority contract, with the original JSON pointer, county, year and scope; object fields and order are unchanged. `native-selected-position-inventory.jsonl.gz` independently inventories every one of26,448 selected2024 original county XML candidate/method positions, full candidate/contest/precinct attributes and source member path. `native-county-checks.json` independently reconciles all99 original county XMLs and status lists,2376 candidate/method controls and statewide candidate/generic sum1663506. `native-xml-schema.json` inventories every XML element/attribute-set in those full original files. Selected2022/2020 source worksheets/rows/columns, all4990 statistical labels and their administrative controls remain exact read-only dependencies, never deduplicated across scopes.

The historical2024 XML candidate roster1653, root VoterTurnout roster1651 and status roster1653 are separate. Root turnout `source_contest_key` stays blank. Lucas omits two Chariton labels from root turnout only; no counts are allocated. `percentReporting="4"` is a client status enum (CompletelyReported), not4% or a vote-completion estimate. Literal county party-label conflicts SPA/SPU/PSI/NoP versus state SOC stay unaltered. Source clocks retain CST/CDT or unspecified timezone, and state release versions do not replace independently clocked county releases.

`primary-2026-identity-schema.json` and `primary-2026-native-positions.jsonl.gz` describe the actually linked June2 primaryEID126082/version377216, not November. They retain99 native county election/version roster entries and1188 Senate candidate/method/county XML positions with full raw attributes, independent county-name/FIPS matches, party labels, choice/contest keys and source clocks. Primary state status1658/1658 is source-scoped and not substituted for the coordinator newsroom sample1659 or for a future November denominator.

`absentee-2026-native-rows.json` preserves the actual October administrative Requested/Issued/Received rows, hierarchy labels, blanks, raw layout lines and page-specific clocks. Missing Received is null, not zero. UD is literal and unexplained. Party denotes registration/administrative categories, not Senate vote choice. Report controls176012/176014/33418 reconcile to99county controls while mixed page dates and issued−requested2 remain visible. These measures cannot establish Senate votes remaining.

`observation-comparison.json` compares bounded second observations only. Same bytes or unchanged setup fields demonstrate that narrow observation, not a true publication cadence, absence of future revisions, or a November readiness guarantee. There is no background polling process or invented refresh promise.

Replay: `research.py seeds` acquires absent SOS/directory sources; `research.py follow` follows bounded scored observed links; the saved `selected-followup-tasks.json` and ledger preserve additional reviewed requests. `inspect.py embedded`, `inspect.py pdfs`, and `inspect.py app` reproduce observed wrapper/app extraction. `native.py`, `state_extract.py`, `build.py`, then `validate.py` run offline and rebuild derivatives/report/inventory/checks. Acquisition reuses pinned IDs by default; it never silently overwrites originals. Requests and Poppler pdftotext are acquisition/extraction requirements; offline validation otherwise uses the Python standard library. No retained dependency/cache directories.
