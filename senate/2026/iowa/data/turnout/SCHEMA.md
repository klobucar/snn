# Iowa turnout data contract

Version 1. All outputs are source derivatives. Source bytes are retained by exact SHA-256 in [source-manifest.json](source-manifest.json); large statewide canvasses are read-only references to coordinator evidence, not duplicate copies. No approved 2026 geography or cross-year/finer-unit crosswalk is asserted.

## County ranking and exact priority

[../county-turnout.csv](../county-turnout.csv) has exactly 99 rows, keyed by five-character `county_fips`. `native_county_label` is the printed canvass county name; `county_native_numeric_id` is blank because the canvass does not provide a separate county ID. FIPS and Census county ANSI IDs come from the retained Census 2020 code table, joined by explicit county name. Page is county 19145. State summary FIPS `19` is a state code, never a county.

`pres2024_candidate_generic_writein_votes` adds the seven printed named-ticket columns and generic Write-in; denominator **1,663,506**. `pres2024_named_candidate_votes` excludes the generic column. Neither is labeled a named-valid-write-in universe: the SOS summary does not identify or validate the generic write-in marks individually. `pres2024_reported_contest_total` includes candidate/generic votes, under votes, and over votes. Ballots/voters/registration are distinct source measures. County order is descending candidate-plus-generic volume with FIPS ascending for ties. Numerators and denominators are exact integers; booleans identify top 15 and minimum 80% membership. No current Senate election is substituted for the actual 2024 presidential contest.

`2024_*`, `2022_*`, `2020_*` participation columns come only from the corresponding SOS turnout report. `total_voters`, `election_day_voters`, `absentee_voters`, election-date `active_registered` and `inactive_registered`, and published percent strings remain separate. Active turnout can exceed 100% in the source. Do not replace any method count with a different source to make it match. The 2022 Senate columns are the other Class III seat/midterm; the 2020 Senate columns are the same Class II seat as 2026.

[priority-set.json](priority-set.json) retains all 99 counties in full order, exact top-15 numerator/denominator, first crossing, preceding set and crossing contribution, separate complete remainder, and source-scoped historical constituents for every county. `unit_key` is only unique inside the given source/vintage. Availability and administrative cases remain explicit. Coordinator acceptance is external to this worker's mathematical calculation.

## Candidate and method extracts

[canvass-candidate-method.csv](canvass-candidate-method.csv) has 7,484 numeric cells: key `(year, source_id, county_fips, native_method, source_column)`. Every county has Election Day, Absentee, Total rows; 2024/2022 additionally publish all three state footer rows, while 2020 publishes only the state Total. `candidate_or_metric_label` transcribes full printed headers, including party when printed. `metric` distinguishes named_candidate, generic_writein, under_votes, over_votes, reported_contest_total. `votes` is an exact integer. `section_text_line`, `source_row_prefix`, `raw_line`, and the retained layout text permit reconstruction; line numbers are scoped to the named contest section. [state-controls.json](state-controls.json) gives every statewide printed column and the original PDF hash. [turnout-report-counties.csv](turnout-report-counties.csv) has 300 county/state rows and election-date registration definitions.

[native-units.csv](native-units.csv) and [native-unit-candidate-method.csv](native-unit-candidate-method.csv) preserve every selected Senate sheet row/candidate/method in the downloaded 2022 and 2020 county exports, plus Scott's actual linked 2020 canvass PDF. Keys use `(source_id, source_sheet, source_row)` plus `source_column` for a cell; `unit_key` records these explicitly. A numeric worksheet name is a native sheet identifier, not a county/precinct code. Scott's printed parenthesized codes are retained in the native ID field. Other units have no separate native ID field and retain the complete printed label. `source_county_total` rows are administrative controls, never constituent precincts. `Total Votes` is the source's candidate-group sum, not ballots cast. Missing cells remain blank; literal source zero remains zero. These are historical reporting rows; names alone do not establish physical precinct, split ballot style, polling place, or equivalent 2026 geography.

`workbook-cells-2022.jsonl.gz` and `workbook-cells-2020.jsonl.gz` preserve all worksheets, sparse row/column positions, original cell types, formulas, merge metadata, and document properties for each successfully parsed county workbook. Originals remain authoritative for formatting and unused ZIP/XML elements. [native-registration-ballots.csv](native-registration-ballots.csv) preserves the separate Registered Voters sheet, all native rows and Total controls. Its zero registration cells may be unpopulated; they are not substituted for election-date registry counts. Workbook creation clocks are source-local/unspecified unless a timezone is printed.

[native-candidate-sheet-context.csv](native-candidate-sheet-context.csv) additionally normalizes all 6,896 printed Registered Voters / Total cells on the selected candidate worksheets, retaining their source row/column and the distinction from ballots. [full-peer-reconciliation.json](full-peer-reconciliation.json) records the reverse read-only comparison of all shared native source fields, including this context, with only explicit display aliases. Scott's native Undervotes/Overvotes labels map to the peer's Under Votes/Over Votes display only for those source metric columns.

## Statistical reports

`statistics-rows.csv.gz` is a compressed CSV of every extracted demographic/age numeric or percentage row in the three years' state/county/precinct statistics reports. Keys are `(source_id, source_page, source_page_line)`; `source_page` is physical PDF page. The seven age bins and source TOTAL are separate; percentages remain printed strings. `source_date` is the printed report/run date, not a registration snapshot assertion. `REGISTERED`, `TOTAL VOTED`, `ABSENTEE`, and `TURNOUT` retain their report scope and are never combined with contest counts. Overlapping demographic groups must not be added together.

[statistics-units.csv](statistics-units.csv) retains each native historical precinct label, including wrapped name lines separated by a literal newline, using the first page/line as `unit_key`. Category Total is a unit control; Grand Totals is a separate county/state administrative control. These labels are not asserted to match the candidate exports by name or number. The source prints addenda/corrections: 2022 Harrison was omitted and added January 27, 2023; the revised 2020 statewide report warns that time-lapse makes its total lower than adding county precincts after Henry/Story were added. [statistics-unparsed-lines.json](statistics-unparsed-lines.json) losslessly retains those textual footnotes rather than converting them into numbers.

## Provenance, replay and bounds

`source-manifest.json` records exact requested link, actual parent, request/final URL, redirects, HTTP status/headers, UTC retrieval, original/stored SHA-256 and byte size. Gzip is lossless over the HTTP entity bytes after transport content decoding. Peer acquisitions lacking redirect history say so explicitly; the final URL is not represented as proof of no redirects. The Black Hawk 2022 alternate is explicitly a tested filename repair from two spaces to one, not a discovered page link. Repeated unsuccessful alternates remain records. Source clocks and certification/publication status are separate from transport status. The Cass link text says canvass/abstract/results, but the inspected PDF internally says Unofficial Final Results; its Election Day heading is not treated as method scope because displayed counts are countywide.

Run `python3 senate/2026/iowa/data/turnout/acquire.py` then `clarity.py` to acquire absent source records; they reuse already pinned evidence. `verify_reused.py` optionally refreshes request/redirect metadata and references identical payloads by hash; differing fresh responses are retained separately and never replace original evidence. Run `build.py`, `native.py`, `statistics.py`, `clarity.py --extract`, `clarity_validate.py`, `reconcile_full_peer.py`, `report.py`, then `validate.py` from the repository root for offline extraction, rankings, reconciliation, report and manifests. The peer comparison reads the retained independent partisanship extracts; it never changes them. Set `PYTHONDONTWRITEBYTECODE=1` to avoid interpreter caches. Poppler `pdftotext` is required; Python standard library plus `requests` for acquisition. No workbook-writing library, retained dependency tree or cache is required. `qa/` contains inspected render previews, not new primary evidence. Every stored artifact must be strictly below 40,000,000 bytes; originals are losslessly compressed. No bytes are truncated or normalized to force agreement.
